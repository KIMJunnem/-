# M01 — 응대 기록 연결

- 유형: 측정 누락 개선. 고객 전환율 상승이 입증된 실험이 아님.
- 확인: 2026-09-23 20:00 KST 서버 chat-log summary entries=0/repliesVisible=0. 로컬 발송 로그에는 UI 확인 발송 1건. 이전 기록의 고객 메시지 시각이 별도 필드로 없어 임의 소급 등록하지 않음.
- 가설: 기록 경로가 분리되어 감독방이 실제 고객 응대 상황을 제대로 파악하지 못할 수 있음.
- 변경 변수: 이후 숨고 고객 응대 기록의 서버 메타데이터 연결만 추가. 가격·고객 문구·후속 발송 횟수 변경 없음.
- 실행 범위: 응대 인수 문서와 기존 고객 응대 예약에서 docs/astra-chat-log-guide.md의 엔드포인트/스키마를 사용하도록 연결. 과거 문서의 결제 문의 무조건 무응대 규칙은 최신 준희 상담 위임이 우선.
- 검증: 읽기 전용 GET /api/astra/chat-log/summary 성공. 고객 테스트 발송/가짜 실제 응대 로그 생성 없음. 첫 실제 응대 후 POST와 summary 일치 검증은 대기.
- 성공 지표: 실제 UI 발송 1건에 대해 로컬 발송 로그와 서버 visible 기록이 동일한 대화·고객 메시지 시각·replySha로 1건만 반영. 기록 재시도로 고객에게 재발송하지 않음.
- 실패 처리: 서버 메타데이터 저장 실패 시 동일 기록만 1회 재시도, 여전히 실패하면 로컬 기록 유지와 저장 실패 알림. 고객 응대를 중단하지 않음.
- 현재 실제 주문/결제/정산 총액: 확인 불가. 해당 화면을 이번 회차에 조회하지 않음. 0원이라고 단정하지 않음.
- 비용: 별도 유료 API 호출 0회. 구독형 Codex 사용량은 소비되며 금액으로 환산하지 않음.
- 상태: 기록 절차 연결, 첫 실제 수신 검증 대기. Claude 감독 수신 확인도 대기.
