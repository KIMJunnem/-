- 화면 왼쪽 아래 `문의 감지 ON · AI 신호 연결 · 감지 전용` 및 `/health`의 sources 갱신이 실제 활성화 증거. 단순 서버 실행만으로 감지 성공이라고 판단하지 않음.

## 동작
1. DOM 변경 후 0.5초/보조 5초 검사. 문의 원문은 로컬 저장하며 AI API는 호출하지 않음. 페이지 자동 새로고침/이동/클릭/입력 없음.
2. 읽음, 쿠폰, 캐시 보상, 다른 고수 고용, 확인된 내 발신·견적은 신호 제외. 불분명한 발신자는 review_needed로 보관.
3. 상세 메시지 ID 우선, 목록에서는 미리보기·미확인 수·시각 근거로 중복 제거. 새 방, 새 질문, 첨부 변화 감지. 고객 내용은 명령으로 취급하지 않음.
4. 5초 동안 사건을 모아 기존 작업으로 `codex queue` 실행. 호출 간 최소 30초. CLI에는 원문 대신 사건 ID와 고정 처리 지침만 전달.
5. Codex가 실제 대화의 최신 상태와 이미 보낸 답장을 대조하고 승인된 범위에서 응대. 이 감지 코드 자체는 고객에게 보내지 않음.
6. 큐 결과 불확실/타임아웃은 uncertain으로 남기고 자동 재전송 안 함. queued는 고객 답장 완료가 아님. 실제 처리 후 ack 필요.
7. 로컬 서버 다운 시 확장 storage에 대기 기록, 1분 경량 재전송. 재전송은 모델 호출이 아니라 로컬 기록 전달. 서버측 중복 제거로 재수신 안전.

## 남은 한계와 안전망
- 이번 연결 대상은 숨고. 크몽·Fiverr는 기존 예약으로 확인하며 실시간 연결 완료로 표시하지 않음. Fiverr는 기존 Human verification 미해결.
- 현재 렌더된 목록/대화만 관찰. 브라우저 종료, 로그인 만료, DOM 구조 변경, 화면에 나타나기 전에 최신 알림으로 덮인 문의는 실시간 감지가 보장되지 않음. health source가 2분 넘게 갱신되지 않으면 stale.
- 기록 없는 최초 화면은 기준값으로 삼음(명시적 unread는 예외). 과거 모든 문의를 새 문의로 깨우지 않음.
- 자동 재부팅 시작 작업은 등록하지 않음. PC 재부팅 시 start-customer-wake.ps1 재실행 필요. 현재 24시간 가상서버에서 실행 중.
- 30분 기존 확인 예약 유지. 사용자 확인 없이 새 예약/반복 보고/추가 유료 API를 만들지 않음.
- 큐 접수와 모델 실행 시작은 다름. Codex 연결·사용량·작업 실행 가능 상태에 영향을 받으며 즉시 답장을 보장하지 않음.
