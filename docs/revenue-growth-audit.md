# 숨고 매출 개선 점검

기준 시각: 2026-09-18

서버의 실제 상태에서 `SAFETY`, `TEST`, `DEMO`, `SIMULATION` 식별자를 제외하고 집계한다. 고객 원문과 개인정보는 지표에 포함하지 않는다. 실결제와 납품은 플랫폼 상태를 확인한 워크플로만 매출로 계산한다.

## 현재 확인된 깔때기

| 단계 | 건수 | 전환율 |
| --- | ---: | ---: |
| 요청 수집 | 157 | 100% |
| 견적 발송 | 154 | 98.1% |
| 고객 답변 | 88 | 견적 대비 57.1% |
| 고용 확정 | 0 | 답변 대비 0% |
| 결제 확인 | 0 | 고용 대비 0% |
| 납품 완료 | 0 | 결제 대비 0% |

현재 검증된 실결제 매출은 0원이다. 테스트 워크플로를 매출로 세지 않도록 했으며, 따라서 가격을 더 낮추는 것보다 답변 이후 고용 전환과 첫 결제 검증을 먼저 개선해야 한다.

## 첫 구매 전환 실험

현재는 견적 154건에서 고객 답변 88건까지 왔지만 고용·결제·납품이 0건이다. 첫 구매를 만들기 위한 실험은 아래 순서로 고정한다.

1. 요청량이 많은 자기소개서·이력서 대필, 문서·글 작성, 통계분석부터 비교한다. 각 서비스의 답변률과 고용률을 따로 기록한다.
2. 첫 메시지에는 고객이 받는 결과물, 확정 범위, 할인가, 예상 일정만 먼저 보여준다. 내부 시스템명이나 긴 기술 설명은 뒤로 미룬다.
3. 고객이 선택할 수 있는 행동은 `1) 진행 2) 샘플 먼저 3) 질문` 세 가지로 제한한다. 답변이 오면 같은 가격과 범위를 반복하지 않고 다음 단계만 한 번 안내한다.
4. 샘플은 한 단위가 완성된 작은 결과물로 제공하며, 숨고 최소 거래금액 15,000원 아래로 내리지 않는다. 본 주문으로 전환하면 샘플 비용을 차감한다.
5. 첫 실제 결제 한 건은 고용 확정→숨고페이 결제 확인→파일 검증→첨부 전송 확인→거래 확정 요청까지 수동 증거를 남긴다. 이 한 건이 끝나기 전에는 전환 성공으로 집계하지 않는다.

서버의 `GET /api/soomgo/revenue-funnel` 응답에는 `firstPurchasePlan`이 추가되어 대상 서비스, 단계별 행동, 안전 가드레일, 성공 지표를 함께 반환한다.

## 우선 실행할 개선

1. 견적 직후 고객이 고를 수 있는 `1) 진행 2) 샘플 먼저 3) 질문` CTA를 유지하고, 선택 결과를 대화별로 기록한다.
2. 고객 답변이 오면 가격·포함 범위·다음 행동을 한 메시지에 제시한다. 이미 받은 정보를 반복해서 묻지 않는다.
3. 서비스별로 요청 수·견적 수·답변 수·고용 수를 분리해 비교한다. 현재 요청량이 가장 큰 이력서/자소서와 문서/글 작성부터 전환 개선을 우선한다.
4. 고용·결제·파일 전달은 실제 플랫폼 확인 전에는 매출이나 완료로 집계하지 않는다. 첫 결제 한 건을 결제 확인→파일 검증→납품→거래 확정까지 끝내는 것을 운영 검증 목표로 둔다.
5. 납품 게이트가 보류하는 경우에는 재전송이나 추가 결제를 자동으로 반복하지 않고, 보류 사유를 운영자 지표에 남긴다.

## 확인 API

내부 화면이나 점검 자동화는 `GET /api/soomgo/revenue-funnel`을 사용한다. 이 응답에는 깔때기 수치, 단계별 전환율, 검증된 결제 금액, 서비스별 구성, 다음 개선 권고가 포함된다. 테스트·안전성 데이터는 자동 제외된다.
