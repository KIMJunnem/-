## 2. `followupText()` 로컬 첫 안내·무응답 후속

- 함수: `followupText()`
- 위치: 1134~1155행
- 첫 안내 사용 위치: `processPendingIntro()` 1493~1501행
- 무응답 후속 큐 저장: `queueNoReplyFollowup()` 1171~1175행
- 무응답 후속 발송: `processPendingFollowup()` 1391~1429행
- 조건: 견적 발송 이벤트를 고객 채팅방과 연결한 뒤 첫 안내로 사용한다. 첫 안내 뒤 약 10분 동안 고객 답장이 없으면 같은 `followupText(event)` 결과를 후속 큐에도 저장한다.

### 공통 전문

```text
문의는 언제든 남겨주세요. 자동 상담으로 기본 내용을 안내하고, 작업 가능 여부와 최종 견적은 담당자 확인 후 안내드립니다. 답변까지 시간이 걸릴 수 있습니다.
안녕하세요! [서비스 라벨 또는 서비스 라벨(주제)] 문의 확인했습니다. [선택적 샘플 안내][선택적 학교 제출 안내][접수 질문]
```

### 선택적 샘플 안내 — 1139~1142행

조건: `quote.sampleAmount > 0`

```text
【샘플 구매 가능】 [샘플 금액]원으로 핵심 일부를 먼저 확인할 수 있고, 본 작업 진행 시 샘플 비용을 전액 차감합니다.
```

### 선택적 학교 제출 안내 — 1143~1145행

조건: 서비스 라벨 또는 주제에 학교·과제·레포트·리포트·수업·강의가 포함됨.

```text
학교 제출용 문서는 제출처의 AI 활용·인용 기준을 먼저 확인해 주세요. 일반 과제·레포트는 접수하고 논문·학위논문·학술 원고는 진행하지 않습니다.
```

### 접수 질문 변형 — 1146~1153행

자기소개서 A:

```text
현재 자기소개서 초안은 어느 정도 준비돼 있나요? 편하게 알려주세요.
```

자기소개서 B:

```text
현재 초안은 ① 있음 ② 없음 ③ 일부만 있음 중 어느 상태인가요? 숫자만 보내주셔도 됩니다.
```

PPT:

```text
PPT로 옮길 원고와 희망 장수, 사용 목적, 필요한 날짜를 보내주실 수 있을까요?
```

기타 서비스 A:

```text
현재 자료는 어느 정도 준비돼 있나요? 편하게 알려주세요.
```

기타 서비스 B:

```text
자료는 ① 준비됨 ② 정리 필요 ③ 아직 없음 중 어느 상태인가요? 숫자만 보내주셔도 됩니다.
```

A/B 선택 조건: 이벤트 ID 또는 서비스 문맥 해시의 홀짝값.

## 3. `safeIntroText()`

- 함수: `safeIntroText()`
- 위치: 1157~1163행
- 발송 위치: `processPendingIntro()` 1493~1501행

조건과 동작:

1. 서버가 준 `event.quote.followupMessage`가 있고 금지 표현이 없으면 서버 문구를 그대로 사용한다.
2. 문구가 비어 있거나 `고용 요청`, `일정 등록`, `진행하실까요`, `진행하겠습니다`, `네 가지 조건`, `고용하기`가 있으면 로컬 `followupText(event)`로 대체한다.

`safeIntroText()` 자체의 고정 고객 문구는 없으며, 위 2번일 때 2절의 문구를 사용한다.

## 7. 실제 발송 로그 대조

확인 자료:

- `server/data/state.json`의 `soomgoLeads[].followupEvidence`와 `followupEvidenceHistory`
- `server/data/state.json`의 `soomgoReplies[]`
- `/api/soomgo/followup-result`가 기록하는 `status`, `conversationId`, `message`, `at`
- `/api/soomgo/reply-result`가 기록하는 일반 서버 답변 전송 증거

| 로컬 문구군 | 확인 가능한 발송 완료 기록 | 발송 뒤 고객 답장 확인 |
|---|---:|---:|
| `followupText()` 첫 안내 | 0건 | 대조 불가 |
| `followupText()` 10분 무응답 후속 | 별도 유형 식별 기록 없음 | 대조 불가 |
| `sendHireWelcome()` 샘플/일반 | 서버에 문구별 발송 증거 없음 | 대조 불가 |
| 거래 확정 감사·리뷰 문구 | 서버에 문구별 발송 증거 없음 | 대조 불가 |

현재 `followupEvidence`에서 확인된 5건은 모두 `expired`이며 발송 완료가 아니다. 기록된 전문은 다음과 같다.

```text
견적 보내드렸습니다. 작업 목적·원하는 결과물 형식·마감일과 참고자료를 보내주시면 기본 범위와 가능한 일정을 바로 안내드리겠습니다.
```

따라서 서버 기록만으로는 위 로컬 문구가 실제 몇 번 발송됐는지와 그 뒤 고객이 답했는지를 신뢰성 있게 계산할 수 없다. 화면에서 문구가 보인 사례가 있더라도 `followup-result`의 `sent` 증거와 문구 유형이 남지 않은 경우에는 발송 로그로 확정하지 않았다.

3. 학교 제출·AI 활용·학술 작업 제외 안내

6. 일반 자료 준비 상태 질문 A/B
