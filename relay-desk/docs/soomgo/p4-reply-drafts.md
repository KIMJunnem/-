## 3. 공통 적용 조건 (코드로 옮길 때)

- **견적을 이미 보낸 대화에서만** 쓴다(`lead.quote.amount > 0`이고 quoteEvidence.status = sent). 견적이 없으면 지금처럼 사람 확인.
- 고객 글에 결제·환불·취소·분쟁·쿠폰·계좌·입금이 있으면 쓰지 않는다(사람 확인 유지).
- 고용 확정된 대화, 수동 관리 목록에 있는 대화에는 쓰지 않는다.
- 같은 대화에서 같은 유형은 한 번만. 두 번째부터는 사람 확인.
- 금액은 `lead.quote.amount`, 날짜는 서버가 이미 계산한 납기(`lead.quote.days` → 오늘 기준 날짜)만. 새 금액·새 날짜를 만들지 않는다.
- 새 messageId·version을 붙인다. 기존 견적 문구는 바꾸지 않는다.

## 4. 문구 초안

### 유형 A — 금액 확인 질문
신호 예: "장당 39000원인가요?", "39,000원 맞나요?", "총 얼마인가요?" (물음표가 있고, 숫자+원 또는 얼마·금액·총액이 있음. '할인', '깎아', '더 싸게'는 제외 → 사람 확인)

```
[고객에게 보낼 문구]
네, 보내드린 견적 기준으로 {serviceSummary} 전체 {quoteAmount}원입니다.
{deliveryDate}까지 보내드리고, 수정 1회가 포함되어 있습니다.
숨고페이 안전결제로 진행되어, 결과물을 확인하신 뒤 거래 확정하시면 됩니다.

분량이 요청서보다 늘어나면 작업 전에 먼저 말씀드리고, 동의하신 뒤에만 진행합니다.
이대로 진행을 원하시면 고용 요청을 눌러 주세요.

[금액 칸]
(보내지 않음 — 이미 보낸 견적 금액을 되짚기만 함)

[담당자 메모]
- messageId: soomgo.followup.price_confirm / version: v1-draft
- 고객이 말한 단가(장당·분당)가 우리 견적 방식과 다르면 쓰지 않는다. 예: 우리는 '전체 금액'인데 고객이 '장당'으로 물음 → 사람 확인. …8113은 이 경우라 자동 대상에서 빠진다[추정 — 견적 방식 확인 필요].
- "기본 범위 시작가" 같은 말은 쓰지 않는다(금액 하나).
```

### 유형 B — 고객 쪽 준비가 늦어짐
신호 예: "좀 기다려야 할 것 같아요", "아직 초안이 안 나와서요", "자료 정리되면 보낼게요", "원고가 아직이에요" (질문 없음, 기다림·아직·정리되면·나오면·준비되면)

```
[고객에게 보낼 문구]
네, 알려주셔서 감사합니다. 급하지 않으니 {materialName} 준비되시는 대로 편하게 보내주세요.
받는 날을 기준으로 다시 날짜를 잡아 말씀드리겠습니다. 보내드린 견적 {quoteAmount}원은 그대로 유지됩니다.

[금액 칸]
(보내지 않음)

[담당자 메모]
- messageId: soomgo.followup.customer_waiting / version: v1-draft
- {materialName}: 서비스별로 서버가 채움 — 문서 "초안", 자막 "영상", PPT "원고", 모르면 "자료".
- "견적 유지"는 준희 확인 필요: 유지 기간을 정하지 않았다. 기간을 못 정하면 이 문장을 빼고 보낸다.
- 9/23 later_contact_thanks("편하실 때 말씀 주시면…")와 겹친다. 합칠지 따로 둘지 준희 결정.
```

### 유형 C — 견적·납기 다시 묻기
신호 예: "견적이 어떻게 되나요?", "언제까지 가능하신가요?", "견적 알 수 있을까요?" (견적·얼마·언제까지·며칠 + 물음, 첨부·새 범위 설명이 같이 오지 않았을 때)

```
[고객에게 보낼 문구]
보내드린 견적 다시 정리해 드립니다.
{serviceSummary} — {quoteAmount}원, {deliveryDate}까지 보내드립니다. 수정 1회 포함입니다.
숨고페이 안전결제로 진행되어, 결과물을 확인하신 뒤 거래 확정하시면 됩니다.

{oneQuestion}

[금액 칸]
(보내지 않음)

[담당자 메모]
- messageId: soomgo.followup.quote_recap / version: v1-draft
- {oneQuestion}: 견적이 달라질 수 있는 빈칸 하나(분량·마감·형식 중 요청서에 없는 것). 모두 있으면 "이대로 진행을 원하시면 고용 요청을 눌러 주세요."
- 고객이 **새 파일이나 새 범위**("밑줄 그은 부분만")를 같이 보냈으면 쓰지 않는다 → 사람 확인. …1234가 이 경우다(금액이 바뀔 수 있음).
- …1904("위 내용을 요청드리려고 하는데 견적이 어떻게 되나요?")는 적용 대상.
```

## 5. 문구가 아닌 것 (따로 보고)

- 숨고 알리미 "거래가 성사됐다면, 고용을 요청해 주세요", "날짜를 클릭하면 요청서 정보를 캘린더에…", "숨고페이 안전결제 잊지 않으셨죠?"가 고객 글로 읽혀 자동답장·결제 확인으로 빠졌다(6건). 알리미 필터 보강 대상이다. 코드 변경이라 이번 지시 범위 밖이다.
