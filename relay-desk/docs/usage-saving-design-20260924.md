## 지금 적용한 절감
- Codex 고객 확인 예약 1개: 평소 10분 → 30분. 상담 중은 실제 고객 마지막 메시지로부터 10분 이내에만 2분, 이후 30분 복귀.
- 이론상 유휴 호출 하루 144회 → 48회(66.7% 감소). 실제 토큰·사용량 절감률은 호출별 문맥 길이와 상담량에 따라 달라 확정하지 않음.
- 새 문의 발견은 예약 지연을 제외하고 최대 약 30분 걸릴 수 있음. 실시간 응대 아님.
- 변화 없는 3시간 보고서 및 Claude ACK 요청 중단. 전환 분석 최소 6시간 간격 + 실제 상담/주문/새 장애/개발 결과 등 새 근거가 있을 때만. 의미 있는 결과·조치 요청이 없으면 감독 호출하지 않음.
- 기존 지침은 변경 감지 후 필요한 부분만, 대화는 신규·변경 건만 상세 조회. 동일 페이지 전문/발송 기록 전문 반복 출력 안 함.
- 유료 API·새 결제·서버 재시작·확장 재로드 없음. 채팅봇 OFF와 크몽 자동 발송 미선택 유지.

## 목표 구조 (미구현)
1. 플랫폼별 감지 전용 수집기: 수신 메시지와 첨부/주문 상태 변화만 로컬 서버로 보낸다. observeEnabled와 autoSendEnabled를 분리하고, 수집 모드에서 가격 계산·답변 생성·발송·고용/납품 자동화를 호출하지 않도록 별도 진입점 사용.
2. 로컬 필터와 영속 대기열: platform + conversationId + messageId 키로 중복 제거. 같은 방 메시지는 5초 동안 묶고, 고객 메시지와 시스템 알림을 분리한다. 최신 줄만 보는 방식 금지. 불확실한 발신자/유형은 조용히 폐기하지 않고 review_needed 사건으로 보관한다. 읽음/쿠폰/보상 단독 알림은 모델을 깨우지 않는다.
3. 상태: detected → pending → claimed(기한부 잠금) → reply_ready → sent_visible / uncertain / waiting_customer. claimed 만료는 작업 회수일 뿐 자동 재발송 허용이 아니다. UI와 기존 발송 기록으로 다시 대조한다. 기계 오류는 local incident, 플랫폼 차단/로그인 만료는 별도 health 상태.
4. Codex 깨우기 어댑터: 실행 중인 Relay 서버가 사용할 수 있는 공식/지원 호출 경로가 실제로 확인되어야 한다. 현재 에이전트의 send_message_to_thread 도구 존재는 로컬 Node 서버에서 호출 가능하다는 증거가 아니다. 비공개 앱 DB 수정·UI 자동 입력·세션 토큰 추출로 우회하지 않는다. 이 연결 확인 전에는 30분 예약 안전망을 제거하지 않는다.
5. 응대 입력: 고객 최신 질문, 필요한 직전 대화, 해당 상품/견적, 미해결 항목만 전달. 전체 과거 보고서/전체 사업 대화는 붙이지 않는다. 정책은 버전 관리하고 변경됐을 때만 갱신. 고객 응대 모델 1개가 답하고 상호 동의용 회의는 없음.
6. 발송은 단일 주체. 상대방·최신 질문·수동 입력·종료/고용 상태 확인 후 발송하며 말풍선 증거로 완료 기록. 최종 납품의 결제/검수/승인 규칙 유지.
