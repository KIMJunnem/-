# Swan 문의·주문 전환 개선 운영

2026-09-23 사용자 승인: "주기적으로 왜 고객들이 답장도 주문도 없는지 고민하고 실천방안 하나씩 실행하고 클로드쪽에도 감독방에 연결해줘".

## 담당과 주기

- 고객 응대·전환 점검 담당: Codex `숨고 메인 채널` (01a099ba-d591-7b30-b6dd-936ca895f051).
- 고객 문의 순회는 기존 10분/상담 중 2분 예약 `automation` 한 개를 유지한다. 한 방에 활성 heartbeat 하나만 허용되므로 별도 예약은 만들지 않는다. 같은 예약에서 마지막 분석 후 3시간이 지난 첫 실행에 전환 분석을 추가한다. 작업폴더 conversion-review-state.json의 lastReviewCompletedAt/nextReviewDueAt으로 중복 분석을 막는다. 기존 중지된 relay-desk 예약과 옛 유료 API 회의·운영 자동 실행은 그대로 중지한다.
- Claude 감독방과는 이 공용 문서, docs/astra-supervisor-handoff-20260923.md, docs/progress.md, docs/conversion-reviews/ 아래의 회차별 결과로 협업한다. 공용 파일 저장은 실제 대화방 알림이나 읽음 확인과 다르다. 직접 감독방 링크는 사용자에게 요청 중이다.
- 수행 결과를 다른 방이 이미 기록했으면 그대로 재실행하지 않는다. 같은 고객에게 두 방이 답하지 않는다. 고객 답장은 이 메인 채널만 맡고, 감독방은 제작 기반·상품·노출·시스템 개선을 맡는다.

## 근거와 지표

- 실제 브라우저의 판매/노출 가능 상태, 수신함, 고객 대화, 주문/결제/정산 화면과 서버 기록을 확인한다. 빈 수신함은 전체 기간 수요 0 또는 매출 0의 증거가 아니다. 로그 0건도 실제 응대 0건으로 간주하지 않는다.
- 채널별로 노출, 프로필/상품 조회, 견적 발송, 읽음, 실제 고객 문의, 우리 답장, 고객 재답장, 범위 합의, 결제 확인, 정산 입금, 환불, 비용을 구분한다. 고객별 식별자는 플랫폼+대화 ID로 구분하되 공유 보고서에 고객 이름/대화 전문은 넣지 않는다.
- 값마다 기간·출처·확인 시각을 적는다. 미확인은 null/확인 불가로 적고 실제 0과 구분한다. 분모가 0 또는 모르면 비율은 계산 불가로 둔다. 같은 고객과 중복 이벤트를 여러 전환으로 세지 않는다.
- 전환율을 비교할 때 같은 기준의 고객군과 충분한 경과 시간을 사용한다. 주문/매출/실제 입금을 혼동하지 않는다. 제작/모델/플랫폼 비용 미확인이면 순이익도 미확인이다.
- 고객 불만·무응답의 원인은 직접 진술이나 재현 증거가 없으면 가설이다. AI끼리 동의했다거나 몇 건 반응이 좋았다는 이유로 인과효과가 입증됐다고 하지 않는다.

## 실행 순서

1. 직전 회차 파일·활성 실험·감독 회신을 먼저 읽는다. 새로운 근거만 수집한다. 진행 중 고객 답변이 있으면 응대를 우선한다.
2. 가장 앞에서 막힌 구간을 찾는다: 미게시/미노출 → 미열람 → 무응답 → 상담 이탈 → 미결제 → 제작/납품 문제. 감지 오류나 미답변 방치가 있으면 판매 문구 실험보다 먼저 고친다.
3. 개선안 후보는 최대 3개, 실행은 한 번에 1개다. 이미 실행한 실험을 계속 관찰 중이면 새 실험을 억지로 추가하지 않는다. 장애 복구와 전환 실험을 구분해 기록한다.
4. 무료이고 되돌릴 수 있는 승인 범위의 개선은 직접 실행한다. 예: 기록 연결, 답변 첫 문장의 질문 대응, 불필요한 접수 질문 하나 제거, 실제 확인된 범위로 소개/샘플 안내 정리, 깨진 링크 수정. 코드 수정은 백업과 해당 검증을 거친다. 운영 중 프로세스·공유 파일을 다른 담당자와 동시에 변경하지 않는다. 외부 상품 수정은 해당 플랫폼의 현재 승인 범위를 대조한다.
5. 실험마다 가설·단일 변경 변수·대상/제외군·변경 전후·시작 시각·주요 지표·관찰 기간·필요 표본·중단/복구 조건·담당자를 먼저 적는다. 표본이 부족하면 판정 보류로 남긴다. 3시간마다 반드시 문구를 바꾸지 않는다.
6. 한 고객에게 같은 질문·후속 연락을 반복하거나 외부 스팸을 보내지 않는다. 허위 후기·경력·성과, 할인 압박, 긴급성 조작은 하지 않는다. 가격을 임의로 내리거나 광고·추가 충전·유료 API를 실행하지 않는다.
7. 할인은 먼저 제안하지 않는다. 고객이 반복해서 할인을 요청할 때만 금액은 유지하고 제작 부담이 작은 추가 서비스 하나를 검토한다. 기본 포함 사항을 특별 혜택으로 말하지 않으며 별도 유료 범위를 무상으로 대폭 확대하지 않는다. 추가 작업 시간까지 기록한다.
8. 효과가 확인되면 유지, 악화되면 복구, 불확실하면 관찰을 이어간다. 매 회차는 docs/conversion-reviews/<날짜시각>-<id>.md에 저장하고 latest.md에는 해당 경로와 상태만 짧게 갱신한다. 중요한 변화만 docs/progress.md에 새 칸으로 연결한다. 다른 방의 기록은 덮어쓰지 않는다.

## Claude 감독 회신

- 지시 수신을 실제로 했다면 docs/conversion-reviews/supervisor-ack.md에 확인 시각·읽은 버전·담당 과제·예상 확인 시점을 기록한다. Codex가 대신 읽음 확인을 작성하지 않는다.
- 시스템/상품/제작 변경은 기존 next-*.md 담당 체계를 사용한다. 신규 과제는 기존 과제를 확인하고 조율한 뒤 배정한다. 고객 메시지 발송, 유료 API 활성화, 납품 승인 우회는 하지 않는다.
- 응대 메인 채널은 감독 회신과 실행 증거를 다음 회차에 대조한다. 파일 등록, 실행, 검증, 고객 반응 확인을 서로 다른 상태로 보고한다.

## 보고 원칙

실제 문제, 실행한 1개 조치, 확인 결과, 다음 관찰만 짧게 알린다. 동일한 보류나 변화 없는 결과를 반복 알리지 않는다. 실행 못 한 것은 이유와 준비 완료 범위를 분리한다. 성과가 없어도 성과를 만들지 않는다.
