# 멍프탑 29,000원 실거래 기반 Relay Desk E2E 검증 보고서

- 기준일: 2026-09-26
- 목적: 2026-09-25 멍프탑 릴스 실거래를 기준으로 Relay Desk가 고객 문의부터 납품·결제까지 비용을 통제하며 끝까지 처리할 수 있는지 점검
- 판정: **거래 상태머신은 끝까지 연결되어 있으나, 영상 제작 착수 전 요구사항 고정과 사용량 사전검사가 강제되지 않아 동일한 비용 누수가 재발할 수 있음**

## 1. 실거래에서 확인된 사실

- 상품: 릴스/쇼츠 1편
- 첫 거래 제시가: 29,000원
- 고객 요구 방향: 영화 예고편식 구성
- 실제 제작 과정에서 고객 의도가 충분히 고정되기 전에 여러 버전을 제작함
- 버전 4~5개가 만들어지며 제작비가 약 17,000~20,000원까지 증가함
- 고객이 영화 「파일럿」 예고편을 레퍼런스로 제시한 뒤 원하는 방향이 명확해짐
- 이후 사용량 부족이 발생해 추가 고객 작업을 정상 처리하지 못한 사례가 이어짐

핵심 원인: **제작능력 부족 자체보다, 제작 전에 고객 의도·레퍼런스·필수 요소를 잠그지 않고 여러 안을 먼저 생성한 운영 문제**

## 2. 현재 코드에서 통과하는 구간

현재 Relay Desk에는 다음 흐름이 구현되어 있다.

1. 고객 요청 접수
2. 서비스 분류
3. 견적 계산
4. 견적 발송 결과 기록
5. 고객 질문 응대
6. 가격 협의
7. 고용 확정
8. 워크플로 생성
9. 결과물 생성 및 파일 기록
10. 수정 요청 처리
11. 추가금 동의 처리
12. 최종 확인
13. 결제 요청
14. 결제 완료 확인
15. 리뷰 요청

기존 내부 로그에서 다음도 확인되어 있다.

- 고객 파일 접수 PASS
- 29,000원 기본 견적 PASS
- 1차 결과물 생성 및 재다운로드 검증 PASS
- 10,000원 추가금 동의 PASS
- 최종 파일 생성·검증 PASS
- 최종 결제금 39,000원 계산 PASS
- 결제 이후 리뷰 요청 단계 PASS
- 잘못된 SRT/PPTX/HWP 납품 차단 로직 동작
- 중복 결제·중복 전송·고용 전 작업 생성 차단 로직 존재

## 3. 멍프탑 실거래를 다시 넣었을 때 발견되는 핵심 공백

### A. 레퍼런스 확정 전 제작을 막는 강제 게이트가 없음

현재 고객에게 “원하시는 느낌이나 참고 영상, 넣고 싶은 문구를 자세히 알려달라”는 안내는 존재한다.

그러나 다음 항목이 채워지지 않아도 제작이 시작될 수 있다.

- 완성 영상 길이
- 레퍼런스/참고 영상
- 반드시 들어갈 문구
- 음악·효과음 분위기
- 장면 순서/핵심 이벤트
- 결과물 용도

따라서 고객이 “영화 예고편처럼”이라고만 말한 경우 시스템이 곧바로 제작으로 넘어가면 어제와 같은 다중 버전 재작업이 재발할 수 있다.

### B. 최초 제작 1안 원칙이 문서상 결정에 비해 실행 게이트로 강제되지 않음

결정 문서에는 “1안만 제작, 여러 버전은 요청 시에만”이 기록되어 있다.

하지만 제작 파이프라인 수준에서 “초안 1개 생성 후 고객 피드백 전 추가 버전 생성 금지”가 독립적인 차단 조건으로 확인되지 않았다.

### C. 사용량/제작능력 사전검사가 고용·납기 확정과 연결되어 있지 않음

현재 사용량이 부족하거나 특정 고급 영상 표현을 만들 수 없는 상황에서도 고객 고용 이후 제작 단계까지 진입할 수 있다.

특히 현재 로컬 video worker는 다음을 지원한다.

- video.inspect
- video.transcribe
- video.cut
- video.subtitle
- video.render
- video.qc

즉 컷 편집·자막·BGM·기본 렌더·검수는 로컬에서 처리 가능하다.

반면 영화 예고편식 고급 전환, 생성형 장면, 복잡한 모션그래픽 등은 별도 모델/도구 의존성이 남는다.

## 4. 멍프탑 실거래를 골든 회귀테스트로 사용할 때의 정답 경로

### 단계 1. 고객 요청
“멍프탑 리뉴얼 행사 릴스 만들어주세요.”

### 단계 2. 견적
- 릴스 1편
- 첫 거래가 29,000원
- 수정 2회 포함
- 결과물 MP4

### 단계 3. 제작 전 요구사항 잠금

다음 네 항목을 확보하기 전 제작 금지.

1. 완성 길이
2. 참고 영상/레퍼런스
3. 반드시 들어갈 문구
4. 음악·효과음 분위기

실거래 기준 예시:

- 레퍼런스: 영화 「파일럿」 예고편 느낌
- 문구: “멍프탑 9월 26일 대개봉”
- 이벤트: 룰렛 이벤트 기간
- 장면: 강아지 영상 → 방문 유도 → 마지막 그립톡 영상 + 행사 이미지
- 사운드: 영화 예고편형 BGM + 효과음

여기까지 완료되면 `BRIEF_LOCKED=true`.

### 단계 4. 제작능력/사용량 검사

제작 시작 전에 아래를 판단한다.

- 현재 Claude/OpenAI 사용량으로 1안 완성 가능한가
- 로컬 FFmpeg worker로 대체 가능한 범위인가
- 외부 영상 생성 도구가 꼭 필요한가
- 예상 추가비용이 29,000원 매출 안에서 감당 가능한가

납품 가능성 또는 비용이 불명확하면 작업 시작을 보류한다.

### 단계 5. 최초 1안 제작

- 고객이 요구하지 않은 복수안 생성 금지
- 1안 제작 후 QC
- 1안 전달 후 고객 피드백 대기

### 단계 6. 수정 처리

- 수정사항은 즉시 여러 번 재렌더하지 않고 한 회차로 모음
- 마지막 수정 메시지 뒤 2시간 후 한 번에 반영
- 급한 마감은 정책 예외 적용
- 기본 수정 2회
- 쇼츠/릴스 3회차부터 가벼운 수정 10,000원
- 큰 수정은 별도 금액 확정 후 진행

### 단계 7. 최종 납품·결제

- 최종 QC 통과
- MP4 전달
- 고객 확인
- 29,000원 결제 요청
- 실제 결제 완료 표시 확인
- 리뷰 요청

## 5. 골든 테스트 실패 조건

아래 중 하나라도 발생하면 테스트 실패로 본다.

1. 레퍼런스/필수 문구가 잠기기 전에 제작 시작
2. 고객 요청 없이 최초안을 2개 이상 생성
3. 사용량·도구 사전검사 없이 고급 영상 작업 착수
4. 수정 요청마다 즉시 별도 렌더를 반복
5. 무료 수정 횟수 초과 후 추가금 동의 없이 제작
6. 실제 결제 확인 없이 완료·리뷰 단계로 이동
7. 품질검사 실패 파일을 고객에게 전달
8. 작업 원가가 매출을 잠식하는데도 자동으로 추가 크레딧 구매를 유도

## 6. 우선 수정 항목

P0
- 영상 제작 전 `BRIEF_LOCKED` 게이트 추가
- 필수 필드: 완성 길이 / 레퍼런스 / 필수 문구 / 음악 분위기
- “알아서 해주세요”는 고객의 명시적 위임으로 기록하고 게이트 통과

P0
- `CAPABILITY_AND_USAGE_CHECK` 추가
- 현재 사용량·로컬 대체 가능성·예상 외부비용을 확인한 뒤 제작 시작

P1
- `FIRST_DRAFT_LIMIT=1` 적용
- 고객 피드백 전 동일 작업의 추가 버전 생성 차단

P1
- 멍프탑 케이스를 고정 fixture로 만들어 회귀테스트에 포함

P2
- 영상 유형별 예상 원가를 기록해 수익성 경고 추가
- 29,000원 상품에서 예상 추가비용이 임계치를 넘으면 사람 확인으로 전환

## 7. 최종 판정

현재 Relay Desk는 **고객 문의 → 견적 → 고용 → 작업 → 수정 → 결제 → 리뷰**라는 거래 흐름 자체는 내부 시뮬레이션에서 끝까지 연결되어 있다.

하지만 멍프탑 실거래를 기준으로 보면, “고객이 원하는 방향을 정확히 잠근 뒤 한 번만 제작하고, 현재 사용량 안에서 납품 가능한지 확인한 후 착수하는 비용 통제 게이트”가 아직 부족하다.

따라서 현 상태를 “완전 무인 상업운영 가능”으로 판정하지 않는다.

다음 릴리스의 성공 기준은 단순히 E2E가 끝까지 도는 것이 아니라:

> **29,000원 릴스 고객을 추가 크레딧 낭비 없이 1안 → 수정 → 최종 납품 → 결제까지 처리할 수 있는가**

로 정의한다.


## 8. 진행 과정 자체를 학습 자산으로 남기는 원칙

이번 멍프탑 건에서 얻은 핵심은 최종 결과물만 저장해서는 부족하다는 점이다.

Relay Desk는 앞으로 각 고객 거래를 하나의 **과정 단위(episode/trajectory)** 로 기록해야 한다.

기록 대상은 다음과 같다.

- 고객이 처음 어떤 표현으로 요청했는지
- Relay Desk가 그 요청을 어떻게 해석했는지
- 어떤 질문을 추가로 했는지
- 고객이 어떤 답을 했는지
- 어떤 시점에 견적·고용·제작을 진행했는지
- 어떤 모델과 도구를 사용했는지
- 각 단계에서 사용량·비용이 얼마나 들었는지
- 최초 결과물이 고객 요구와 얼마나 맞았는지
- 고객이 무엇을 수정 요청했는지
- 수정 요청이 처음 정보 부족 때문인지, 고객의 사후 변경인지
- 어떤 레퍼런스를 받은 뒤 품질이 개선됐는지
- 몇 번의 제작/렌더가 발생했는지
- 최종 결제 여부와 실제 매출
- 거래가 끝난 뒤 다시 한다면 어느 단계를 바꿔야 하는지

즉 학습 데이터는 단순히

`고객 요청 → 최종 정답`

형태가 아니라

`상황 → 판단 → 행동 → 고객 반응 → 비용 → 수정 → 결과`

전체 흐름이어야 한다.

### 적용 방식

1. **원본 거래 로그 보존**
   - 실제 고객 메시지와 내부 행동 순서를 시간순으로 남긴다.
   - 개인정보는 필요한 범위에서 가리거나 식별자를 분리한다.

2. **과정 요약 생성**
   - 거래 종료 후 “잘한 판단 / 잘못한 판단 / 불필요한 비용 / 다음번 규칙”을 별도 요약한다.

3. **성공·실패 구간 표시**
   - 성공한 응대는 그대로 재사용 가능한 예시로 저장한다.
   - 실패한 응대도 삭제하지 않고 왜 실패했는지 원인과 함께 보존한다.

4. **하위 모델 승계**
   - 상위 모델은 최종 답안만 남기는 것이 아니라 중간 판단 기준도 남긴다.
   - 하위 모델은 다음 거래에서 비슷한 상황이 나오면 이전 과정의 판단 순서를 우선 참고한다.

5. **회귀 시뮬레이션**
   - 실제 거래 episode를 고정 fixture로 만들어 새 코드·새 모델·새 프롬프트가 과거 실수를 반복하는지 다시 돌린다.

### 멍프탑 episode에서 반드시 학습할 내용

- “영화 예고편처럼”은 제작 지시가 아니라 추가 구체화가 필요한 신호였다.
- 레퍼런스를 받기 전에 여러 버전을 만드는 것은 비용 낭비로 이어졌다.
- 고객이 직접 준 영화 「파일럿」 예고편이 방향을 잠그는 핵심 정보였다.
- 29,000원짜리 작업에서 17,000~20,000원의 제작비가 들어간 것은 손익상 위험 신호다.
- 따라서 다음 유사 요청에서는 먼저 참고 영상·필수 문구·길이·사운드 방향을 확보하고 1안만 만든 뒤 피드백을 받아야 한다.

### 최종 원칙

Relay Desk의 목표는 “정답 문장을 많이 저장하는 것”이 아니라 **실제 고객을 상대하면서 어떤 순서로 판단해야 돈을 덜 쓰고 더 정확하게 납품할 수 있는지를 축적하는 것**이다.

따라서 앞으로 모든 고객 거래는 결과물뿐 아니라 **진행 과정 자체가 학습 데이터**로 남아야 한다.
