## 1. 지금 판정 흐름

숨고 요청이 `document_writing`(문서/글 작성)으로 분류되면 가격은 아래 순서로 정해진다.

1. **작업 종류: `pricing-table.js:38~45 documentWorkType`**
   - 어떤 칸을 보나:
     - 속기·교정은 서비스 줄(`purpose`)을 먼저 보고, 없으면 상세를 본다.
     - 상세(`detail`)는 purpose, topic(작성 주제), scope, notes, volume을 이어 붙인 글이다.
   - 판정 순서:

     | 순서 | 이런 말이 있으면 | 작업 종류 | 줄 |
     |---|---|---|---|
     | ① | 서비스 줄에 속기·타이핑·녹취, 또는 상세에 "녹취록"·"녹음 파일을 문서로" | stenography(녹취 타이핑) | 41 |
     | ② | 서비스 줄에 교정·교열·윤문, 또는 상세에 교정·교열·윤문·맞춤법·첨삭 | proofreading(교정) | 42 |
     | ③ | 상세에 양식·서식·편집·레이아웃·**디자인만**·깔끔하게·다듬·**정리만**·"내용은 다 되어" | formatting(서식 정리) | 43 |
     | ④ | **나머지 전부** | writing(새 글 작성) | 44 |

   - **문제:**
     - ③이 좁다. "디자인"(만 없이)·"보기 좋게"·"인포그래픽"·"포스터"·"카드뉴스"·"도식"은 ③에 걸리지 않아 모두 ④ **새 글 작성**으로 간다.
     - 그래서 기존 보고서 16쪽을 보기 좋게 디자인해 달라는 요청이 새 글 16쪽 가격(147,000원)으로 나간다.
2. **금액·납기: `documentQuote`(115~164)**
   - 작업 종류의 가격표를 쓴다. 가격은 기본 금액에 쪽 수를 더하는 방식이고, 40쪽을 넘으면 넘는 쪽에 따로 매긴 단가를 쓴다.

     | 작업 종류 | 기본 | 기본에 포함된 분량 | 추가 단가 |
     |---|---|---|---|
     | writing | 21,000원 | 2쪽 | 쪽당 9,000원 |
     | formatting | 15,000원 | 5쪽 | 쪽당 1,500원 |
     | proofreading | 21,000원 | 4쪽 | 쪽당 5,000원 |
     | stenography | 21,000원 | 10분 | 분당 1,800원 |

   - 납기(documentLeadDays 55~59):
     - formatting: 20쪽 이하면 당일~1일
     - writing·proofreading: 5쪽 이하면 당일~1일, 15쪽 이하면 1~2일
3. **수정 횟수: `isSchoolAssignment`(82~85)**
   - 이용 목적·서비스·주제·메모·범위 칸 중 하나에 학교 과제·**과제**·수업·레포트·리포트·교양·교수님·조별·팀플·수행평가가 있으면 학교 과제로 본다.
   - 학교 과제로 보면 수정 3회 → **2회**가 되고, "3번째 수정부터는 1회 10,000원"이라는 문장이 붙는다. 견적 문구 버전 뒤에는 `-school`이 붙는다.
   - **문제:** "과제" 한 단어만으로 걸린다. "기관 **연구과제**"·"정부 과제"·"기업 과제"도 학교 과제가 되어, 일반 문서가 받아야 할 수정 3회 대신 2회가 나간다.
4. **결과 반영: `relay-server.js:3326~3339`**
   - documentQuote 결과로 금액·문구·수정 횟수를 덮어쓴다.
   - 문서가 아닌 서비스(PPT·자막)도 3341줄에서 같은 `isSchoolAssignment`를 쓴다. 그래서 학교 과제 판정을 고치면 PPT·자막의 수정 횟수 문장에도 똑같이 적용된다.
5. **사람 확인 경로**
   - 견적 결과를 `autoSend: false, manualReview: true, reason`으로 만들면, 8070~8105줄이 판정을 기록하고 `quoteReviewAttention.upsertQuoteReview`가 준희 확인 알림 목록에 한 번 올린다.
   - 외국어 교정(3355줄)과 자소서(3150~3175줄)가 이미 이 경로를 쓴다.

M03 재현 결과는 이번 실행에서도 같았다: M1 21,000원 writing(학교), M2 147,000원 writing, M3 32,000원 formatting, M4 21,000원 writing.

## 2. 수정안 (가격 숫자는 바꾸지 않는다)

새 판정 순서는 아래와 같다. ①②는 지금과 같다.

| 순서 | 조건 | 결과 |
|---|---|---|
| ① | 속기(지금과 같음) | stenography |
| ② | 교정(지금과 같음). 교정이 같이 있으면 교정이 먼저다 | proofreading |
| ③ **새로** | 그림·도표를 **새로 만드는** 말: 인포그래픽·포스터·카드뉴스·도식·다이어그램·일러스트·배너·전단·리플렛·브로슈어·로고·썸네일 | **범위 확인(scope_check)**: 금액 없음, 자동 발송 안 함, 준희 확인 알림 |
| ④ **새로** | "디자인"이 작업 요청으로 쓰임("디자인해/작업/부탁/만", "보기 좋게·예쁘게·깔끔하게 디자인/꾸며"), 또는 서비스 줄에 "디자인", 또는 **기존 문서**(기존·이미 작성된·완성된·초안·원본·가지고 있는) + 보기 좋게/예쁘게/꾸며 | 내용 유지 말(내용은 그대로·유지·수정 없이·손대지, "내용은 다 되어", 양식만·서식만·디자인만·레이아웃만·편집만)이 **있으면 formatting**, **없으면 범위 확인** |
| ⑤ | 지금 ③의 서식 정규식 그대로 | formatting |
| ⑥ | 나머지 | writing |

"디자인"이 주제어로만 쓰인 경우("디자인 트렌드 분석 보고서 작성")는 ④에 걸리지 않고 지금처럼 writing으로 간다.

### 2-1. 디자인·인포그래픽·포스터·카드뉴스·도식 → 범위 확인

- 견적은 `amount: 0`, `message: ''`, `autoSend: false`, `manualReview: true`로 만든다. 여기에 `scopeCheck: { kind, question }`을 붙인다.
- reason: "디자인·시각 자료 요청이라 작업 범위 확인이 필요합니다(자동 금액 없음)."
- 기존 알림 경로(1-5)를 그대로 탄다. 이 요청은 판매 범위가 아닌 순수 디자인 제작일 수 있으므로, 준희가 가능 여부를 먼저 정한다.
- **확인 질문 한 줄 초안** (준희가 직접 보낼 때 쓰는 용도. 자동 발송 문구가 아님):
  - 시각 제작·디자인이 불분명할 때(visual_design·design_unclear):
    > 원하시는 게 글과 표를 보기 좋게 정리하는 것인지, 그림·도표를 새로 그리는 디자인 작업인지 여쭤봐도 될까요?
  - 이 문구를 자동 경로에 넣게 되면 messageId·version을 새로 받아 기록해야 한다(문구 원칙). 이번 수정안에는 넣지 않았다.
- 숨고 카테고리가 디자인 쪽이면 애초에 document_writing으로 오지 않는다(판매 안 하는 카테고리는 soomgo-auto-rules 1)에서 삭제). 이 수정은 **문서/글 작성으로 분류된 요청 안의** 디자인 요청만 다룬다 [추정: 카테고리 매핑 파일은 열어 보지 않음].

### 2-2. 기존 문서를 보기 좋게·정리·편집·디자인 → formatting 조건

- 기존 문서 + 디자인/보기 좋게 요청이 있을 때:
  - 내용 유지 말이 **있으면** formatting이다(가격표 그대로, 16쪽이면 32,000원).
  - 내용 유지가 **불분명하면** 범위 확인으로 보낸다(kind `existing_doc_redesign`).
- 확인 질문 한 줄 초안:
  > 가지고 계신 문서의 내용은 그대로 두고 제목·문단·표 모양만 정리해 드리면 될까요?
- 지금 ③(깔끔하게·다듬·정리만 등)으로 formatting이 되던 입력은 그대로 formatting이다(F2·F3·F4, 기존 시험 입력 모두).

### 2-3. 학교 과제 판정

- 학생 단서가 **있으면** 학교 과제다:
  - 학생 단서: 학교 과제·수업·레포트·리포트·교양·교수님·조별·팀플·수행평가·대학생·학부생·"대학(교) 과제/레포트/수업/강의"·기말·중간고사
- "과제"만 있는 경우:
  - 앞에 **연구·기업·회사·정부·국책·국가·용역·사업·기관·지원**이 붙은 "○○ 과제"는 먼저 지운다. 띄어 써도 같다.
  - 그러고도 "과제"가 남아 있으면 학교 과제다(예: 이용 목적 "기타: 과제").
- "대학"만 단독으로 쓰인 경우("대학 홍보 자료")는 학교 과제로 보지 않는다.

## 5. 남은 문제 (이번 수정안 밖)

- **W2처럼 주제에 "포스터"가 들어간 글 작성 요청도 범위 확인으로 빠진다.** 틀린 금액을 보내는 대신 준희 확인이 한 번 느는 쪽으로 보수적으로 잡았다. 실제로 자주 걸리면 그때 좁힌다.
- **R1: "회사 시장 분석 리포트"는 여전히 학교 과제다(수정 2회).** 지시는 "레포트·리포트"를 학생 단서로 두라고 했으므로 이번에는 바꾸지 않았다. 바꿀지는 준희가 정한다.
- **"수업"이 선생님의 수업 자료일 때도 학교 과제로 본다.** 지금과 같은 동작이다.
- **지금 ⑤(원래 ③)의 "깔끔하게·다듬"은 새 글 요청("깔끔하게 써 주세요")도 formatting으로 보낼 수 있다.** 이번 수정 범위 밖이라 그대로 두었다. 합성 입력으로 재현해 보지는 않았다.
- **범위 확인 질문 두 줄은 초안이다.** 자동 문구로 쓰려면 messageId·version 등록과 준희 승인이 필요하다.
- M03 두 실제 대화는 이 수정과 관계없이 Codex 상담 절차(M03 적용 규칙)대로 다룬다. 이 문서로 고객에게 새 견적을 보내지 않는다.
