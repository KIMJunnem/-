  - (나) 확장을 지우고 다시 설치하거나 다른 폴더에서 새로 불러와 저장소가 비었을 때(기본 true)
  - (다) **애초에 저장값이 ON이었던 경우**: 준희가 패널 버튼이 아니라 채팅 탭이나 Chrome을 닫아 멈췄다면, 저장값은 ON 그대로 남는다. 확장은 1분마다, 그리고 탭이 닫힐 때와 Chrome을 켤 때 채팅 탭을 다시 연다(auto-update.js 24~35줄, 60~61줄, 102~110줄 `ensureChatTab`). 그러면 ON으로 다시 보인다.
- **ON이어도 고객에게 보내는 동작은 막혀 있다.**
  - 정책 `soomgoChat.sendEnabled=false`(astra-relay-operating-policy.json, 9/23 16:05)이면 서버 `/api/soomgo/control`이 `chatSendEnabled:false`를 준다(relay-server.js 8861~8866줄).
  - 채팅봇은 이 값이면 멈춤으로 보고 발송·첨부·결제 버튼을 누르지 않는다(chat-content.js 127~141줄).
  - `customerRoomFallback.enabled=false`, `claudeEnabled=false`도 확인했다.

### 판단

- 재시작·발행이 켠 것은 아니다.
- (가)~(다) 중 무엇인지는 모른다. 서버에는 채팅봇 상태의 **마지막 값**만 남고 이력은 없어서(relay-server.js 7902~7913줄 botStatus) 06:57 전후를 거슬러 볼 수 없다.
- decisions 6절의 "꺼진 채팅봇·심박 없음"이 탭이나 Chrome을 닫은 상태를 뜻했다면 (다)일 가능성이 가장 크다 [추정].
- 참고: 채팅봇 폴더의 manifest.json·auto-update.js·customer-wake-background.js는 오늘 12:01, customer-observer.js는 12:06에 바뀌었다. 06:57보다 뒤라 이번 ON과는 관계없다.

### 고치려면 (수정안만. 확장 수정이라 적용은 별도 지시와 준희 승인이 필요)

1. soomgo-chat-bot/chat-content.js
   - 17줄 `enabled: true` → `false`
   - 499줄 초기화 때 `enabled: false, autoSend: false, autoReply: false`로 바꾼다.
   - 이렇게 하면 새 설치나 저장소 초기화 때 꺼진 채로 시작한다.
2. soomgo-chat-bot/auto-update.js `ensureChatTab`(24~35줄): 저장값 `enabled === false`이거나 서버 `chatSendEnabled === false`이면 채팅 탭을 자동으로 열지 않는다.
3. chat-content.js 476~480줄 패널 표시: `chatSendEnabled:false`일 때 "ON"이 아니라 "기록만(발송 꺼짐)"으로 보이게 한다. ON이 실제 발송처럼 보여 생기는 혼동을 줄인다.
4. 적용 순서: 백업 → run-all → 발행 → 채팅봇 패널이 "기록만"으로 보이는지 준희 확인.
