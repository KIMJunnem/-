# Relay Desk 무인 운영 설계 및 적용 기록

## 운영 방식
상주 Relay Desk 서버와 브라우저 확장프로그램을 유지한다. 화면 변화·새 메시지·고용·결제·결과물 상태는 일반 프로그램이 감지한다. 대화 답변과 제작·수정·채점 등 실제 판단이 필요한 작업만 기존 Astra API 경로를 사용한다. Codex 예약 실행으로 매번 전체 대화를 읽는 구성은 도입하지 않는다.

## 역할
- 요청 봇: 요청서 감지, 발송 비용 및 서비스 조건 확인, 견적 접수.
- 채팅 봇: 새 고객 메시지와 대기 업무 확인, 대화방 이동, 플랫폼 결과 확인.
- Relay Desk 서버: 고객별 기록, 결제 및 파일 조건 검증, 작업 대기열, AI 호출 및 사용량 기록.
- Astra: 자연어 상담과 제작·수정·채점. 단순 화면 감시는 호출하지 않는다.

## 이번 적용
- 두 봇의 상태 패널 변경은 화면 감시 대상에서 제외하고 외부 변화는 250ms로 묶는다. 정지 상태에서 스스로 다시 실행하는 반복을 막는다.
- 과거 배포의 자동 재개 처리를 제거한다. 사용자가 선택한 정지는 업데이트로 해제하지 않는다.
- 서버 점검 정지를 디스크에 보존한다. /api/soomgo/control에서 조회·변경하며 새 견적/답변/고용 API 및 제작 큐 실행을 막는다. 진행 중인 외부 작업의 취소를 보장하는 기능은 아니다.
- 두 봇은 서버 정지 여부를 최대 5초 간격으로 확인한다. 서버 연결 실패나 불명확한 응답은 정지로 취급한다.
- 같은 고객의 답변 요청이 동시에 도착하면 서버는 두 번째 요청을 409로 돌려보내 AI 중복 실행을 막는다. 완료 응답은 기존 메시지 ID 기록을 재사용한다.
- 대기 업무는 마지막 방문이 오래된 순으로 선택한다. 방문 기록과 방 상태를 저장한 뒤 이동한다.
- 고객 메시지 목록 처리를 업무 목록보다 먼저 시도한다.
- 이전 파일 전송이 불확실한 경우 파일 재전송뿐 아니라 새 결제 요청도 보류한다.

## 거래 흐름의 기준
고용 확인 → 합의한 금액의 결제 요청 → 실제 결제 확인 → 제작 및 파일 수정이 포함된 검수 → 최종 검수와 요청 형식 확인 → 해당 고객방에 파일 전달 → 포함된 무료 수정 → 서비스 완료 및 플랫폼의 거래확정 가능시간 확인 → 감사 및 리뷰 요청.
결제 요청과 실제 결제 완료는 구분한다. 전송 버튼 클릭만으로 전송 완료로 기록하지 않는다. 추가금은 동의된 금액만 사용한다.

## 검증 결과와 제한
모의 브라우저에서 수동 정지 보존과 정지 중 응답성 검사 2개, 기존 채팅 회귀 검사 23개, 중복 동작 방지 검사 9개가 통과했다. 요청 형식·파일 전달 계약 검사도 통과했다. 테스트는 고객 메시지를 실제 전송하지 않았다.
실제 Chrome 제어는 시간 초과가 발생했다. 현재 실행 중인 확장프로그램이 새 버전으로 교체되었는지와 실제 파일 업로드 성공은 확인되지 않았다. 따라서 완전 무인 영업 검증 완료로 표시하지 않는다. 서버는 점검 정지 상태다.

## 운영 전 남은 확인
1. Chrome의 설치된 확장 경로와 버전 확인: 요청 0.1.31, 채팅 0.2.62.
2. 실제 테스트 대화방에서 결제 확인·첨부·전송 확인·목록 복귀까지 검증.
3. 여러 탭이 동시에 켜졌을 때 단일 실행 소유권 확보. 현재 서버 답변 동시 실행은 막지만 모든 브라우저 클릭의 탭 간 잠금까지 보장하지는 않는다.
4. 긴 제작 작업 중 수동 정지가 들어올 때 실행 중 작업의 취소·재개 정책 검증.

이번 변경 검증에는 유료 Astra API를 호출하지 않았다. API 사용량은 0이며, Codex 자체 사용량과는 별개다.
